# Announcements

Administrators can compose an announcement in iOS Settings → Administration → Announcements or the web Account & privacy administration area. Compose a shared title (80 characters), a short push notification body (500 characters), and full announcement text (10,000 characters). Push previews show the short body; My Lists cards and Activity entries show the full text. Older announcements and clients fall back to their original message for push delivery. Preview both versions, send a test to your own registered devices, then confirm the broadcast. A test saves a `[Test]` announcement card and Activity entry for the sending administrator only, then requests push delivery to that administrator’s devices. Tests use separate IDs so the same draft can still be broadcast afterward. The history shows recipient and pending counts.

Choose **Everyone** or **Selected accounts** in either admin composer. Search by name, email, or username and select up to 1,000 accounts. Each broadcast snapshots verified, non-suspended accounts in that audience. An empty or invalid selection is rejected, never treated as Everyone. Recipient selection is stored with the broadcast and cannot change when retrying its ID. Delivery creates one Activity entry per recipient, including the sender. Push alerts use the existing APNs/FCM configuration and are sent unless the recipient has turned off **Feature tips & announcements** and has a registered device. The preference is account-wide, defaults on, and can be changed in iOS notification settings or the web account screen. Other notification categories are unaffected. Opening an iOS announcement push opens Activity.

Deploy the API and apply `CreateAnnouncements`, `AddAnnouncementDismissals`, `AddAnnouncementAudience`, `AddAnnouncementPushBody`, and `AddAnnouncementReadState` before releasing clients. Existing and new accounts default to announcement pushes enabled when no preference has been saved; explicit opt-outs remain off. Device/OS push permission is still required. Announcements also appear as dismissible cards on My Lists, and dismissal is saved per account across devices. Dismissing a card before the worker processes it also suppresses that pending push. Dismissal does not remove Activity entries or change future announcement preferences. No broadcast is sent by deployment itself.

The client supplies a stable UUID per announcement. Retrying that UUID returns the existing broadcast; changing its content returns a conflict. The background worker processes up to 25 recipients every 10 seconds with PostgreSQL row locks, resuming pending work after restarts. Suspended/unverified recipients are skipped at delivery time, and push consent is rechecked then. History counts are attempts, not provider/device delivery receipts. Push delivery is best effort, matching other Hushful pushes; a process crash after provider acceptance but before the database commit can repeat a push on recovery.

Run focused tests against a disposable PostgreSQL database whose name ends in `_test`:

```sh
DATABASE_HOST=127.0.0.1 DATABASE_PORT=55439 DATABASE_USERNAME=wishlist DATABASE_PASSWORD=wishlist DATABASE_NAME=hushful_announcements_test swift test --filter Announcement
```

The integration test is skipped unless `DATABASE_NAME` ends in `_test` and `DATABASE_URL` is unset. Never point it at a live database: it exercises broadcast fan-out across all eligible test accounts. Tests do not require APNs/FCM credentials.

The Activity screen has separate Activity and Announcements segments. The Announcements badge counts unread recipient records across the full archive; opening an announcement marks it read, while opening Activity does not. My Lists dismissal also marks that announcement read. The paginated archive retains dismissed announcements and survives Activity clearing; it only contains announcements delivered to the signed-in account. Reading an announcement does not dismiss its My Lists card. Announcement push taps open the Announcements segment in iOS. The overall Activity/app badge counts regular unread activity plus unread announcements, without counting their legacy Activity copies twice.
